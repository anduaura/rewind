The problem

Logs and traces tell you what happened.
They don't let you run it again.

When a production incident occurs in a microservices system, the state is gone, the timing is gone, and "works on my machine" is the default outcome.

🕳️

State is gone

The Postgres rows, Redis keys, and in-memory state that caused the failure have already changed by the time you look.

⏱️

Timing is gone

Race conditions, timeouts, and clock-sensitive code paths can't be reproduced without the exact wall-clock state from the incident.

🤷

Works on my machine

Staging has different data, different traffic, and different infrastructure. The bug only manifests in production, where you can't attach a debugger.

For AI agents

From narrating incidents
to verifying fixes.

Every observability AI today does the same thing: ingest logs and traces, produce a plausible English narrative of what probably went wrong. It can't verify the hypothesis — the incident is gone. A .rwd snapshot changes that.

Without rewind

Observability AI

Reads logs and traces. Produces a narrative: "null deref likely caused by upstream contract change." Opens a PR you still have to fully verify, because it has no way to confirm the fix worked.

With rewind

rewind + agent

Replays the frozen incident, patches the code, replays again, reports a hard pass/fail. Opens a PR that says: "I reproduced this, applied this fix, and the replay now passes." Trustworthy enough to merge.

1

Replay the incident

The agent runs rewind replay against the .rwd snapshot. The failure reproduces deterministically — same clock, same DB responses, same network calls.

2

Propose a patch

The agent reads the snapshot (what was recorded) and the service code (what was running). It proposes a targeted fix via tool_use.

3

Apply and re-replay

The patch is applied to a sandbox copy of the service. The same snapshot is replayed against the patched code.

4

Hard pass/fail signal

If the replay returns 2xx: verified fix. If not: iterate with the failure fed back as context. The agent gets a signal, not a vibe.

python agent.py
── Step 1 — confirm bug reproduces ─────────────────────────────
status_code=500 passed=False
details: JSONDecodeError: Expecting value (worker returned 204 No Content)

── Step 2 — ask Claude for a patch ─────────────────────────────

body: {"job_id":7,"status":"ok","worker_result":null}

How it works

Record in production. Replay anywhere.

A two-phase approach: an eBPF agent captures the causal chain in a bounded ring buffer, and the replay engine re-executes it deterministically — controlling clock, randomness, and network.

1

Attach

The eBPF agent attaches to running containers without restarts, code changes, or sidecars. Works with any language and any framework.

tcp_sendmsg kprobe captures HTTP + DB
sys_exit tracepoint captures syscalls
Ring buffer holds ~5 min of traffic
2

Flush

When an alert fires, flush the ring buffer to a .rwd snapshot. Nothing is written to disk until you trigger it.

rewind flush --window 5m
Flushed 47 events to incident.rwd
~5-10 MB compressed
3

Replay

The replay engine overrides the clock, intercepts outbound calls, and re-fires the triggering request — deterministically.

Clock → libfaketime volume-mounted
Network → mock server returns recorded responses
Exit 0 on match · Exit 1 on divergence
Capture coverage

The full causal chain, not just HTTP logs.

Most incidents involve more than one service call. rewind captures everything that participated in the failure — correlated by W3C traceparent headers.

🌐

HTTP / REST

Method, path, status, headers, body (opt-in), and W3C traceparent for cross-service correlation.

inbound + outbound
🔌

gRPC

HTTP/2 HEADERS frame parsing via HPACK — service and method paths extracted without decoding protobufs.

HTTP/2 wire
🐘

Postgres

Wire protocol queries and responses, including DataRow decoding for touched rows — without a DB proxy.

wire protocol
⚡

Redis

RESP protocol commands and replies. GET, SET, LPUSH, ZADD — every call correlated with its response.

RESP wire
🗄️

MySQL & MongoDB

MySQL wire protocol and MongoDB BSON framing — captured at the socket level via port-matched eBPF probes.

wire protocol
🕰️

Clock & random

clock_gettime and getrandom return values captured via sys_exit tracepoint and replayed deterministically.

Zero instrumentation

Attaches to
running containers.

The eBPF agent loads into the Linux kernel and attaches kprobes to tcp_sendmsg and tcp_recvmsg — without restarting containers, injecting sidecars, or changing a single line of application code.

It works with any language, any framework, and any runtime. Python, Go, Java, Node, Rust — all captured identically at the socket layer.

CO-RE (Compile Once, Run Everywhere) field access means the same binary runs on Linux 5.10 through 6.x on x86_64 and arm64 — no recompilation for different kernel versions.

Enterprise

Built for regulated industries.

The agent and CLI are open source (Apache 2.0). Enterprise features are available on the hosted collection plane and in the self-hosted server.

🔐

Encryption at rest

AES-256-GCM via age. --key flag or REWIND_SNAPSHOT_KEY env. SOC 2 / ISO 27001 compliant.

🔑

RBAC + OIDC

Token-scoped read/write/admin levels. RS256 JWT validation against any OIDC provider — Okta, Azure AD, Google.

📋

Audit log

Structured JSON record of every capture, flush, and replay. Tamper-evident. Required for PCI-DSS and HIPAA environments.

🔒

TLS + secret management

TLS on the collection server. Keys from Vault, AWS Secrets Manager, or Azure Key Vault via URI scheme.

🧹

PII scrubbing

rewind scrub redacts headers, strips bodies, and filters paths before sharing snapshots. GDPR delete by user ID.

📊

Compliance reports

rewind compliance outputs machine-readable SOC 2 / GDPR evidence: encryption status, RBAC setup, retention config, audit log summary.

☁️

HA object storage

S3, GCS, and Azure Blob backends for the collection server. Stateless replicas with leader-election retention jobs.

📅

Retention policies

Max-age and max-size TTL cleanup. rewind retention --max-age 30d --max-size 50GB --delete

🔔

Auto-trigger

PagerDuty and Opsgenie webhook listener. Flushes automatically when an alert opens — HMAC-SHA256 signature verified.

Get started

Your first replay in 15 minutes.

Linux 5.10+, Docker Compose, and root or CAP_BPF access are all you need.

Install the binary:

curl -Lo rewind https://github.com/anduaura/rewind/releases/latest/download/rewind-x86_64-unknown-linux-musl && chmod +x rewind && sudo mv rewind /usr/local/bin/
1

Start your application

rewind attaches to any running Docker Compose stack — no restarts required.

$ docker compose up -d
2

Attach the agent

The agent auto-detects services from your compose file and starts capturing immediately.

$ sudo rewind attach
Detected 2 service(s): api, worker
Recording…
3

Trigger an incident & flush

After observing the problem, snapshot the ring buffer. The agent keeps running.

$ rewind flush --window 2m --output incident.rwd
Flushed 47 events to incident.rwd
4

Inspect the snapshot

See exactly what was captured: HTTP calls, DB queries, syscalls, timestamps.

$ rewind inspect incident.rwd
5

Replay it

The engine overrides the clock, mocks outbound calls, and re-fires the trigger. Exit 0 = match, exit 1 = divergence.

$ rewind replay incident.rwd --compose docker-compose.yml
status: 201 == 201 ✓
body: match ✓
